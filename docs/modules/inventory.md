# Inventory

> Master data + stock ledger for all SKUs the business sells/services. **One product table (`InvProduct`)** feeds every channel — store, online ecommerce, wholesale, repair-centre. Default behaviour: every product is sellable everywhere unless explicitly restricted via `isListedInShop` etc.

### API routes (`src/app/api/inventory/`)
- `units`, `categories`, `groups`, `brands`, `warranty-terms` — CRUD masters.
- `products` — `InvProduct` CRUD (search, list, create, edit, photo upload).
- `vouchers/optional` — GET. Consolidated listing of the six non-GL voucher types (SALES_ORDER, PURCHASE_ORDER, GRN, CHALLAN, REJECTION_IN, REJECTION_OUT). Params: `from`, `to`, `page`, `limit`, optional `type` (single, restricted to the six), optional `search` (reference / description / partyName). Returns `{ rows, total, page, limit }`; each row includes `stockDir` (`IN`|`OUT`|`NONE`) and the inlined `lines` for right-click expand. Powers `/office/inventory/optional-vouchers`.
- `vouchers` — `InvVoucher` (GRN / PO / Challan / Sales / Rejection / Sale Return / Purchase Return) with three-tier lifecycle (cancel/delete/hard-delete). PATCH `/api/inventory/vouchers/[id]` accepts the full editable payload (date, description, party fields, paymentMode/Account/Terms/dueDate, refNumber/Date, shipping, roundOff, discount, amountReceived, lines incl. freeQty) and supports **both DRAFT and POSTED** vouchers. DRAFT edits are a plain update. **POSTED edits run in a single transaction** that (a) reverses the original stock ledger + cached InvProduct.stock, (b) posts a reversal JE and marks the original JE as CANCELLED (audit chain preserved in the JE list), (c) replaces lines + header fields, then (d) re-posts stock + GL from scratch using `postInvVoucherToGl`. **The voucher reference is preserved** — same row, same `id`, same `reference`. CANCELLED / soft-deleted vouchers return 409. `POST /[id]/duplicate` clones a voucher (header + lines) into a fresh **DRAFT** with a sequential reference via `invNextRef`.
- `stock-journal`, `stock-ledger`, `physical-stock` — stock movement tracking.
- `reports/stock-summary` — GET returns `{ method, rows }`. Accepts `?method=LAST_COST|WEIGHTED_AVG|FIFO|LIFO` (default `LAST_COST`). Each row carries master fields (id, sku, name, stock, lowStockThreshold, costPaise, pricePaise), grouping (`unit`, `group`, `brand`, `category`), a `valuation` block (unitCost, value, method, optional `fallback`), and `isLow`. UI at `/office/inventory/stock-summary` (Tally-style report) + `/office/inventory/inventory-details` (per-SKU drill).
- `products/[id]/transactions` — GET returns `{ product, transactions[] }` for a single SKU; transactions are POSTED `InvVoucherLine` rows joined to `InvVoucher` with computed `paymentStatus` (PAID/PARTIAL/UNPAID); accepts optional `?from` / `?to` date params.
- `naming-config` — GET returns the singleton `InvNamingConfig` row (or hard-coded defaults if the table is empty). PUT upserts the row. Permission `inventory:manage`.
- `attribute-masters` — GET (list all; optional `?categoryId=` filters to that category + global rows), POST create. `attribute-masters/[id]` — PATCH, DELETE. Permission `inventory:manage`.

## Permissions (gate keys)

- `inventory:manage` — broad master-data permission for units / categories / brands / warranty terms / `InvProduct`. (Listed under `module: admin` in seed.)
- `inventory:view:branch` / `inventory:edit:branch` — branch-scoped view / create+post for users limited to their assigned branches (R3 Front Desk, R4 Despatch get these by default).
- `inventory:view:org` / `inventory:edit:org` — org-wide view / create+post across any branch (admin/owner only).
- `inventory:voucher:cancel` / `delete` / `hard-delete` — three-tier on stock vouchers (GRN, PO, etc.).

## Prisma models (file: `prisma/schema/inventory.prisma`)

- `InvProduct` — single SKU master. Used by store, online, wholesale, repair-centre. Has fields for identifiers (sku, barcode1-3, ean1-3, upc1-3, modelNo), categorisation (unitId, categoryId, groupId, brandId, warrantyTermId), shop-listing flags (isListedInShop, slug, shopBadge, shopDescription, galleryJson, specsJson, shopCategory), GST fields (gstRate, hsnCode, taxability — added via `db push` — see Step 4 gotcha).
- `InvUnit`, `InvCategory` (tree), `InvProductGroup`, `InvBrand`, `InvWarrantyTerm` — masters.
- `GstRate` — GST rate master. Fields: `rate Decimal(5,2)`, `label String @unique`, `description String?`, `isActive Boolean`. Seeded by `bootstrap-seed.ts` with Indian slabs (0%, 0.25%, 3%, 5%, 12%, 18%, 28%). No FK on InvProduct yet — wiring the dropdown on the product form is a follow-up.
- `InvAttributeMaster` — category-wise attribute key definitions. Fields: `key` (machine key, e.g. `ram`), `name` (display label, e.g. `RAM`), `categoryId?` (null = global, non-null = restricted to one category), `sortOrder`, `isActive`. Unique on `(key, categoryId)`. Drives the Attributes dropdown on the product form and the `attr` token in naming convention. **Dummy data** — seeded by `dummy-shop.ts` (7 demo categories + 43 attributes); wiped by `hard-clean.ts`. Production users populate via UI.
- `InvProduct.attrsJson` (`Json?`) — flat `{ key: value }` object storing per-product custom attribute values (e.g. `{"ram":"8GB","os":"Windows 11"}`). Keys should match `InvAttributeMaster.key` entries.
- `InvVoucher` + `InvVoucherLine` — GRN / PO / Challan / Sales / Rejection / Stock Journal / **Sale Return** / **Purchase Return**. Cross-references Accountancy via `JournalEntry`. `InvVoucherType` enum includes `SALE_RETURN` and `PURCHASE_RETURN` (added 2026-05-12). Return vouchers carry three extra fields: `refNumber` (original voucher ref), `refDate` (date of original), `refVoucherId` (FK back to the source `InvVoucher`). **As of 2026-05-14: `branchId` (FK to `Branch`) is REQUIRED on every InvVoucher** — drives per-branch stock balance, list filtering, and reporting.
- `InvStockLedger` — append-only stock movement log (qty deltas keyed to `InvProduct`). **As of 2026-05-14: `branchId` is REQUIRED**; stamped from the parent voucher at post time. Indexed `(productId, branchId, date)` for per-branch ledger queries.
- `InvProductBranch` — **per-branch stock balance** (added 2026-05-14). Composite PK `(productId, branchId)`. One row per (product × branch) pair holding the cached running stock count. Mirrors the `Account.balance` pattern: updated atomically via `upsert` on every voucher post/cancel/delete/restore. Voucher post code in `src/app/api/inventory/vouchers/[id]/post/route.ts` is the canonical source — also called from POS `src/app/api/pos/sale/route.ts`, voucher PATCH (re-post path), and lifecycle reversals (cancel / delete / restore).
- `InvNamingConfig` — singleton config (one row) driving auto-fill of `InvProduct.name` (offline), `InvProduct.shopSubheading` (online display name), and `InvProduct.slug` from the master selects. Three independent token lists (`nameFields` / `onlineNameFields` / `slugFields`) share one fallback chain (`fallbackFields`). Each token entry: `{ kind, enabled, defaultValue?, literal? }`. Seeded once by `bootstrap-seed.ts`; survives `hard-clean.ts` (user-set config).

### Architectural rule

`InvProduct.stock` is a **running cache** updated by Purchase/Sale/StockJournal posts and seeded from opening at master-save time. Postgres treats `NULL + n = NULL`, so:
1. New products are inserted with `stock: 0` (not null) — see `syncProductCacheFromOpening` which returns `0` when no opening qty is given.
2. Setting opening on a product overwrites `stock` to the opening qty (last-write-wins). Subsequent vouchers move from there.

For per-product stock-value display, **always use `productClosingValue(p)`** — never `p.stock * p.costPaise / 100` inline. This keeps null/zero handling consistent.

## Common workflows (wiring)

1. **Create a product** — `/office/inventory/products` → "+ New product" → `InvProductFormFields` (tabs) → POST `/api/inventory/products` → if Opening tab filled, `productOpeningValue` writes `openingValue` and `syncProductCacheFromOpening` seeds `stock` + `costPaise` so Balance Sheet's Stock-in-Hand reflects it immediately.
2. **GRN inward** — `/office/inventory/grn` → "+ New" → POST `/api/inventory/vouchers` (type=GRN) → creates `InvVoucher` + `InvVoucherLine[]` + writes `InvStockLedger` qty+ rows + posts journal to AP.
3. **Sale via shop** — `/shop/checkout` → `ShopOrder` → confirmed → emits `InvVoucher` (type=SALES) → ledger qty- + posts AR/Revenue journal.
4. **Adjust on-hand stock** — `/office/inventory/physical-stock/new` → enter counted qty per product → POST handler treats qty as new on-hand value, computes delta, writes `InvStockLedger`, updates `InvProduct.stock` cache.
5. **Tally journal voucher with inventory consumption** — `JournalVoucherDialog` (from accountancy module, accessible anywhere via `useJournalVoucherStore`) → POST `/api/finance/journal-vouchers` with `stockItems` per line → atomic Voucher + JE + STOCK_JOURNAL InvVoucher carrier + InvStockLedger entry. Items only allowed under INCOME/EXPENSE ledgers (gated by `isStockEligibleAccount` from accountancy).
