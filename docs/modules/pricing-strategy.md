# Pricing Strategy

> **Cost → margin → sell price** for every `InvProduct`. The **additive-margin engine** (`StrategyPoint` points: `base + brand + category + group`) defines the markup; per-item knobs (`costMethod`, `marginPercent`, `priceOverridden`) override where needed. The module reads inventory masters, writes back to `InvProduct.effectiveSalePricePaise`, and shares its cost-resolution path with stock valuation so pricing and balance-sheet stock value agree. _(The legacy `PricingStrategy` scope→markup engine was dropped 2026-05-31 — the additive points are now the single engine.)_
>
> **Materialized effective price.** `effectiveSalePricePaise` (formerly `pricePaise`) is the single value every sale transaction charges. It is *materialized* from `effectiveSalePriceSource` (formerly `saleSource`, enum `EffectiveSalePriceSource`): `SAVED` → `savedSalePricePaise` (the human price, also the barcode source), `COMPUTED` → cost × `marginPercent` (live), `STRATEGY` → the engine output (live). `recomputePricesForProducts` rewrites it after every transaction and the Freeze action re-materializes it immediately. POS / Sale voucher / storefront read it **raw** via `products/lookup` + `productPublic`, which expose it under the stable field name `pricePaise` (boundary). The old read-time `effectiveSellPaise()` helper was removed.

### API routes (`src/app/api/pricing-strategy/`)
- `items` — GET only. Returns one `PricingItem` row per active `InvProduct`: product fields, effective cost method (`product.costMethod ?? OrgDefaults.valuationMethod`), resolved cost (via `resolveCostBatch`), the per-unit **`additionalCostPaise`** (shipping/courier, GST-exclusive — from the Costing layer, kept SEPARATE so `resolvedCostPaise` stays pristine), and the computed sell price from the **additive-margin engine** (`additiveMargin.ts`, with the additional cost folded in **before** GST) — `computedPricePaise` (MRP-capped), `rawComputedPricePaise` (pre-cap), `cappedAtMrp`, and `appliedMarkupPct` = the summed margin. (The legacy `strategyId`/`strategyName` fields are retained as always-`null` for back-compat; `appliedFlatPaise`/`appliedRoundingPaise` are always 0.)
- `costing/pool` — GET only. The shipping/courier pool snapshot: nominated group + its ledgers, the waiting entries (posted debits with `remaining > 0`, each with allocated/dismissed/remaining buckets), and summary totals (`poolTotalPaise` / `allocatedTotalPaise` / `dismissedTotalPaise` / `waitingTotalPaise`). `{ configured: false }` when no pool group is set. Read-only relative to the GL.
- `costing/draws` — GET (history; `?productId=` / `?sourceJournalLineId=` filters) + POST (record an `ALLOCATION` or `DISMISSAL` draw against a posted debit). POST validates with `costPoolDrawCreateSchema` (discriminated by `kind`) and **re-checks `amountPaise ≤ entry remaining` server-side**. **Writes only `AdditionalCostAllocation` — never a journal entry.**
- `costing/draws/batch` — POST. Voucher-driven allocation: one ALLOCATION `AdditionalCostAllocation` per line (`costPoolAllocateBatchSchema`, carrying `sourceInvVoucherId` + the inward `date`), with the SUM capped against the source entry's remaining. Fed by `AllocateVoucherDialog` (which reads `/api/inventory/vouchers?types=PURCHASE,GRN&status=POSTED` + `/api/inventory/vouchers/[id]` for lines). No GL impact.
- `costing/draws/[id]` — PATCH (edit amount / per-unit / quantity / note — kind, source entry and product are fixed; `amountPaise` is re-capped against the source line minus every *other* draw, via `costPoolDrawUpdateSchema`) + DELETE (undo a draw, restoring its remaining). No GL impact.
- All three `costing/*` routes + the items extension are gated by `inventory:manage`.
- `items/[id]` — PATCH only. Updates per-product knobs (`costMethod`, `marginPercent`, `priceOverridden`, `effectiveSalePricePaise`, `stdCostPaise`). Setting `effectiveSalePricePaise` implicitly flips `priceOverridden=true` unless the caller explicitly clears it. **Enforces MRP cap**: refuses (HTTP 400) if `effectiveSalePricePaise > InvProduct.mrpPaise`.
- `sale-price` — PUT only. Bulk-freezes the saved Sale Price from Update & Print Labels: writes `effectiveSalePriceSource` + (for `SAVED`) `savedSalePricePaise` (MRP-capped) + `salePriceFrozenAt` + `savedProfitPaise`, then **immediately** calls `recomputePricesForProducts` so `effectiveSalePricePaise` reflects the new source without waiting for a voucher.
- `apply` — POST. Bulk-recomputes `InvProduct.effectiveSalePricePaise` from the additive-margin engine (STRATEGY source) + per-item `marginPercent` (COMPUTED source). Body: `{ productIds?: number[]; forceOverridden?: boolean }`. Default scope = all active products **excluding** `priceOverridden=true` **and `effectiveSalePriceSource = SAVED`** (saved prices are never clobbered). When `productIds` is given, those exact products are processed (overridden ones still skipped unless `forceOverridden: true`). Returns `{ updated, skipped, errors[] }`. Wrapped in `prisma.$transaction`.
- `points` — GET / PUT (file: `points/route.ts`). The single org-wide additive-margin `StrategyPoint` set, used by the `/strategies` editor **and the live engine**. **GET** returns the grouped shape `{ base, brand:{}, category:{}, group:{}, stockBand:{}, ageBand:{}, moveBand:{} }` (refKey → points; map keys are master ids as strings, band keys for bands). **PUT** validates via `strategyPointsSaveSchema` (`pricingSchemas.ts`), drops zero-point / empty-refKey entries, then atomically **replaces** the whole set (`deleteMany` + `createMany` in one `$transaction`); returns `{ saved }`. Both gated by `inventory:manage`. The saved points now drive `InvProduct.effectiveSalePricePaise` (via `additiveMargin.ts` → recompute/apply) — there is no separate live engine anymore.
- _(removed) `strategies` + `strategies/[id]` CRUD — the `PricingStrategy` model was dropped; the additive `StrategyPoint` set (`points`) is the only pricing config now._

## Permissions (gate keys)

- `inventory:manage` — single key for everything in this module (points PUT, items PATCH, apply, sale-price freeze). No pricing-specific permission exists or is needed; pricing is treated as part of inventory administration. Seeded by `bootstrap-seed.ts` as part of the standard inventory permissions.

## Prisma models (file: `prisma/schema/inventory.prisma`)

- **`PricingStrategy` — REMOVED.** The scope→markup rule model and its CRUD/matcher/`/strategies` API were dropped (2026-05-31). The additive `StrategyPoint` set (below) is now the single pricing engine.

- **`CostMethod` enum** (`enums.prisma`) — five values used by both pricing and stock valuation:
  `WEIGHTED_AVG`, `SIMPLE_AVG`, `FIFO`, `LAST_INWARD`, `MONTHLY_AVG`.

- **`StrategyPoint`** (`inventory.prisma`, `@@map("strategy_points")`) — one row per non-zero point in the additive-margin model edited at `/strategies`. Fields:
  - `dimension StrategyPointDimension` — which axis this point belongs to.
  - `refKey String @default("")` — `""` for `BASE`; the master id (as a string) for `BRAND` / `CATEGORY` / `GROUP`; a band key for the band dimensions.
  - `points Decimal(8,2) @default(0)` — the margin-percent contribution (negatives allowed).
  - `@@unique([dimension, refKey])` — at most one row per (dimension, refKey); a singleton org-wide set (no name, no multiple strategies). Zero-valued points are not stored.
  - Seeded by `bootstrap-seed.ts` with a default `BASE`/`""`/`0` row.

- **`StrategyPointDimension` enum** (`enums.prisma`) — `BASE | BRAND | CATEGORY | GROUP | STOCK_BAND | AGE_BAND | MOVE_BAND`. The three `*_BAND` members are reserved for stock-level / idle-age / movement banding; persisted + validated but not yet editable in the UI.

- **`AdditionalCostAllocation`** (`inventory.prisma`, `@@map("additional_cost_allocations")`) — one row per slice of a shipping/courier pool entry consumed. `kind AdditionalCostAllocationKind` (`ALLOCATION | DISMISSAL`, `enums.prisma`); `sourceJournalLineId` → the POSTED `JournalLine` debit it draws from (`onDelete: Cascade`); `sourceInvVoucherId` → the PURCHASE/GRN `InvVoucher` the freight was spread from (`onDelete: SetNull`, null on dismissals — lets the history group draws into a voucher-like document); `amountPaise` (drawn from the pool, both kinds); ALLOCATION-only `productId` + `perUnitPaise` (GST-exclusive surcharge) + `quantity`; `note`, `date` (the inward voucher date), `createdById`. **Decision-support only — the GL is never written; this table only *reads* JournalLine.** `OrgDefaults.shippingPoolGroupId` (`org.prisma`, FK → `AccountGroup`, `onDelete: SetNull`) nominates the pool group; admin-chosen so bootstrap leaves it null and it survives reseed. Hard-clean treats `additional_cost_allocations` as transaction data (in `TRANSACTION_TABLES`). Dummy demo lives in `dummy-vouchers.ts`.

- **`InvProduct` columns the module reads/writes**: `costMethod`, `marginPercent` (per-item override of the strategy's markupPercent), `priceOverridden` (lock flag), `effectiveSalePricePaise` (materialized sell price — written by `recomputePricesForProducts`, `apply`, items PATCH), `effectiveSalePriceSource` + `savedSalePricePaise` + `salePriceFrozenAt` + `savedProfitPaise` (the saved-price freeze fields, written by `sale-price` and Edit Product / Item Import). `mrpPaise` is read for cap enforcement but never written here.

## Key components / library

- **`src/modules/pricing-strategy/lib/resolveCost.ts`** — cost-basis resolver. `resolveCostBatch(products, method)` returns `Map<productId, ResolvedCost>`. Maps `CostMethod` → unit cost in paise:
  - `WEIGHTED_AVG_COST` / `FIFO` / `LAST_PURCHASE_COST` — delegate to **`valueStockBatch`** in `src/modules/inventory/lib/valuation.ts` so stock valuation and pricing share one source of truth. Converts the valuation module's rupees → paise.
  - `MONTHLY_AVG_COST` — `groupBy InvStockLedger` over IN rows in the current calendar month, weighted `Σ(amount) / Σ(qty)`. Fallback: `no-month-history` → product's cached `costPaise`.
  - `STD_COST` — reads `InvProduct.stdCostPaise` verbatim. Fallback: `no-std-cost` → cached `costPaise`.
  - Single-product wrapper `resolveCost()` exists but is unused by current call sites (both routes call the batch directly).

- **`src/modules/pricing-strategy/lib/additiveMargin.ts`** — the sell-price engine (replaces the dropped `resolvePrice.ts`/`matchStrategy.ts`):
  - **`loadStrategyPoints()`** — loads the org-wide point set, grouped `{ base, brand{}, category{}, group{} }`.
  - **`additiveMarginPct(product, points)`** — `base + brand[brandId] + category[categoryId] + group[groupId]` (missing = 0).
  - **`additivePrice(costPaise, marginPct, mrpPaise?, gstRatePct?)`** — markup on cost, GST-inclusive, MRP-capped: `cost_incl = round(cost × (1+gst/100)); price = round(cost_incl × (1+margin/100))`, then clamp to MRP. Returns `{ pricePaise, rawPricePaise, cappedAtMrp }`. Mirrors the `/strategies` preview so preview === live.
  - **`additivePriceWithSurcharge(baseCostPaise, additionalCostPaise, marginPct, mrpPaise?, gstRatePct?)`** — the ONE documented home for the "add the shipping surcharge BEFORE the GST gross-up" rule. Adds the GST-exclusive `additionalCostPaise` to the base, then calls `additivePrice`. The base is never mutated. Used by the items API; the Items + Update & Print Labels pages apply the same fold-in client-side.
  - `matchStrategy.ts` now contains only `loadLastSaleAgeDays` (the days-since-sale helper the items API still surfaces).

- **`src/modules/pricing-strategy/lib/costPool.ts`** — the read side of the additional-cost layer (READ-ONLY vs the GL). `getShippingPoolGroupId()`; `getPoolSummary(asOf?)` (waiting entries + totals, summing POSTED **gross debits** to pool ledgers minus `AdditionalCostAllocation` consumption); `getEntryRemainingPaise(journalLineId)` (the server-side draw guard); `getCurrentAdditionalCostByProduct(ids)` — **DERIVE RULE = the most recent ALLOCATION draw's `perUnitPaise` per product** (isolated here; switch to SUM/AVG/windowed by editing only this function).

- **Pages** — `strategies/page.tsx` (additive-margin **points editor** + live preview), `items/page.tsx` (virtual-scrolled per-SKU pricing grid).

## Common workflows

1. **Set the org-wide default margin** — `/office/pricing-strategy/strategies` → set **BASE POINTS** (e.g. `25`) → Save. Every product's margin starts from this base. (Bootstrap seeds `BASE = 25`.)
2. **Bump a brand / category / group** — same page, give that master positive (or negative) points. A product's margin = `base + brand + category + group` points it falls under. Save.
3. **Set a per-item margin (COMPUTED source)** — `/office/pricing-strategy/items` → edit a row, set `marginPercent`. With `effectiveSalePriceSource = COMPUTED` the price follows `cost × (1 + marginPercent)` instead of the additive points. Useful for one-off SKUs.
4. **Lock a manual price** — edit a row, set `effectiveSalePricePaise` directly. `priceOverridden` flips to `true`; bulk-apply will skip this product unless `forceOverridden: true`.
5. **Bulk-recompute everything** — `POST /api/pricing-strategy/apply` with `{}` → updates every non-overridden active product. Passing `{ productIds: [...] }` scopes to that list; passing `{ forceOverridden: true }` also overwrites locked items.
6. **Attribute shipping/courier cost to products** — one-time: Settings → Org Defaults → pick the **pool group** (e.g. "Courier & Shipping Cost Pool"), create a ledger per courier under it, and book courier payments to those ledgers as usual (Dr courier / Cr Cash) in accountancy. Then `/office/pricing-strategy/costing`: each posted courier debit shows as a waiting entry → **Allocate** the product-freight share to the product(s) with a per-unit surcharge, **Dismiss** the office-courier remainder. The per-unit cost flows into Items / Update & Print Labels pricing automatically.

## Recent decisions / gotchas

- **Cost method resolution** — `product.costMethod ?? OrgDefaults.valuationMethod` (default `WEIGHTED_AVG`). There is no strategy-level cost-method tier anymore (it died with `PricingStrategy`).
- **2026-05-25 — Virtual scrolling on Items table**: large product lists now render via virtual scroller in `items/page.tsx`. See commit `1e67df6`.
- **2026-05-25 — Layout uncapped**: `layout.tsx` is full-width (no `max-w-7xl`) so the Items table can breathe. See commit `006ad9c`.
- **`lastPurchasePaise` in the items API is a *cached snapshot*** — `items/route.ts:152` returns `InvProduct.costPaise`, which is the running cost cache updated by purchase posts, not a historical receipt record. Editing it does not retroactively change past invoices. Field is named for UX clarity, not as a historical lookup.
- **`MONTHLY_AVG_COST` uses local-server time** — `resolveCost.ts:142` `startOfCurrentMonth()` calls `new Date()` with no timezone normalization. On a non-IST deploy this would shift the month boundary by the host offset. Fine for the current Windows/dev setup; if production moves to UTC infra, anchor to IST.
- **Items routes have no DELETE by design** — `/api/pricing-strategy/items` exposes GET (list) + `[id]` PATCH only. Items follow `InvProduct` lifecycle: to remove a row from the pricing UI, delete or deactivate the product in inventory. (Open design note — not a hard contract.)
- **Cost resolution is shared with stock valuation** — `resolveCostBatch` delegates `WEIGHTED_AVG_COST` / `FIFO` / `LAST_PURCHASE_COST` to `valueStockBatch` in the inventory module. Any change to the valuation engine affects pricing too. Do NOT inline a parallel implementation here.
- **One pricing engine now** — `StrategyPoint` (additive points → summed margin) is the single source. `recomputePrices.ts`, `items` and `apply` all materialize `effectiveSalePricePaise` from `additiveMargin.ts` (STRATEGY source) / per-item `marginPercent` (COMPUTED) / `savedSalePricePaise` (SAVED). The old `PricingStrategy` scope→markup engine + `pickStrategy`/`applyStrategy` were dropped — the `/strategies` preview and what actually sells are now the same formula, so they always agree.
- **`StrategyPoint` is a singleton** — `@@unique([dimension, refKey])` plus the empty `refKey` for `BASE` means there is exactly one org-wide point set; the PUT replaces it wholesale. There is intentionally no "multiple named strategies" concept here.
- **Band dimensions reserved** — `STOCK_BAND / AGE_BAND / MOVE_BAND` points exist in the schema + `additiveMargin` loader but contribute 0 (not editable / not applied yet).
- **Strategies are not protected math** — the module is NOT listed in `docs/completed-and-protected.md`. Behavior may still evolve; treat `resolveCost` / `additiveMargin` as the source of truth but not yet frozen.
- **Voucher numbers, never GL refs** — the Costing page shows the **originating voucher number** (Payment / Purchase / …) + its type for each pool entry/draw, resolved via `resolveSourceVoucherRefs` (`costPool.ts`) from `Voucher.journalEntryId` / `InvVoucher.journalEntryId`. The internal `GL-…` `JournalEntry.reference` is intentionally **not** surfaced to users. **TODO:** expose GL refs admin-only for diagnosis. (Standing rule across the app — don't surface GL numbers in user-facing UI.)
- **Additional-cost layer never touches the GL** — the Costing page / `AdditionalCostAllocation` / `costPool.ts` only *read* `JournalLine` aggregates and write their own table. No journal entry, no valuation change, no Balance Sheet / P&L / Day Book impact. The owner's hard constraint: the accountancy module stays untouched. If a future change ever needs to post here, stop and get approval.
- **Additional cost is GST-exclusive and added before the GST gross-up** — `perUnitPaise` is stored excl-GST (like `resolvedCostPaise`); it slots into the cost basis *before* `× (1+gst)`. The base `resolvedCostPaise` is never merged into — it stays the pristine procurement reference (so past-cost comparisons aren't polluted); additional cost is always its own column/component.
- **Pool = gross POSTED debits** — `getPoolSummary` sums gross debits to the pool ledgers (literal "any posted debit"); a courier-payment reversal/credit is not auto-netted — clear it via **Dismiss**. If a source entry is later cancelled (`JournalEntry.deletedAt`), it drops out of the pool and its draws show an **orphaned** badge in the history (still feeding product cost until deleted).
- **Sale/POS margin display deferred** — surfacing the landed (base + additional) cost in the POS / Sale-voucher margin badge is not done; POS is a protected surface and the seam wasn't traced. Pricing-strategy (Items + Update & Print Labels) fully reflects the additional cost.

## Out of scope / deferred

- **DELETE endpoint for items** — see gotcha above. If a "remove from pricing view without touching inventory" workflow is needed, build it then.
- **Pricing history / audit log** — no record of what changed when, who applied a bulk update, or what the previous price was. Add when needed.
- **Multi-currency** — single-currency (paise) only.
- **Tiered pricing** (retail / wholesale / repair-centre price columns) — schema doesn't support multiple sell prices per SKU yet; that lives in the broader inventory roadmap.
