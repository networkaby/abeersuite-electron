# Completed and protected surfaces

Treat everything listed here as **preserve-first**. Refactors and styling are fine; behaviour or output changes require explicit user approval. If a protected surface is intentionally changed, update this file in the same commit.

## Completed list

- **Accountancy** — voucher engines (Sale, Purchase, Receipt, Payment, Contra, Journal Voucher, returns, GL postings), Day Book, Trial Balance, Balance Sheet, P&L, Receivables/Payables (bill-wise), Cash/Bank Book, Ratios, GST hub + HSN classification, ledger outstandings. Don't touch math paths (`effectiveLedgerBalance`, `aggregateClosingAsOf`, `aggregateRange`, `netProfitLoss`) without an explicit accounting task. **Balance Sheet closing-stock valuation became method-aware in PR 3 of noble-boole (2026-05-28)** — the BS now reads `OrgDefaults.valuationMethod` (default `WEIGHTED_AVG`) and the UI has a dropdown to preview other methods (`LAST_INWARD | SIMPLE_AVG | FIFO | MONTHLY_AVG`); the underlying `productClosingValue` rewrote to walk `InvStockLedger` + opening master fields after the `costPaise` cache column was dropped. **2026-06-01 — credit is deny-by-default:** `checkCreditLimit` now treats `Account.creditLimit` NULL exactly like 0 (no credit); only an explicit POSITIVE limit permits a credit sale. New customers (person/company/portal-register) are created with `creditLimit: 0`, and the POS account-snapshot maps NULL→0 (no more "Unlimited"). **Note:** enforcement still lives ONLY in the POS sale path; the office Sale voucher (`/api/inventory/vouchers`) does not yet call `checkCreditLimit`. See [docs/modules/accountancy.md](modules/accountancy.md).
- **POS** — counter-based tills, shift lifecycle (open → sales → close with variance), tax-inclusive pricing default, thermal ESC/POS receipt printing, payment splits. **2026-05-31 — materialized effective sale price:** the InvProduct selling-price column was renamed `pricePaise` → `effectiveSalePricePaise` and is now a *materialized* value rewritten from `effectiveSalePriceSource` (renamed from `saleSource`; `SAVED`→`savedSalePricePaise`, `COMPUTED`→cost×margin, `STRATEGY`→engine) by `recomputePricesForProducts` after every transaction and immediately on Freeze. POS + the Sale voucher read it **raw** via `products/lookup`, which exposes it under the stable field name `pricePaise` (the boundary that keeps the shop/POS DTOs unchanged). The read-time `effectiveSellPaise()` helper was removed. **2026-06-01 — POS price re-sync:** PosScreen now re-fetches prices once when a sale starts (a customer is picked) via the new lightweight `GET /api/inventory/products/prices` (id + `effectiveSalePricePaise` + `mrpPaise` only — no GST/cost cascade), so a counter idle for hours picks up prices re-frozen meanwhile. It patches the in-memory list by id; cart lines stay snapshotted so a sale in progress is never repriced. **2026-06-01 — shift-close payment breakdown:** the Close-shift dialog, post-close report and thermal printout now show a "Payments collected this shift" tally across ALL methods (Cash, UPI, Card, Wallet, Cheque, Bank Transfer — only those with activity, custom per-counter labels honoured), derived at read-time from `InvVoucherTender` + RECEIPT debits per the counter's routing accounts (`buildShiftTenderBreakdown` in `shiftMath.ts`). Cash math, GL and the cash reconciliation are unchanged — the tally is informational. **Pending:** POS return flow (sale-return voucher + receipt print page + multi-partial-return guard). See [docs/modules/pos.md](modules/pos.md).
- **Inventory** — unified `InvProduct` master (shop + warehouse + POS + repair), attribute masters + `attrsJson`, multi-branch stock, GST/HSN cascade (product → group → org → null), Branch Transfer, Manufacturing Journals, Physical Stock, Bill of Materials, voucher top-bar/action-bar UX. See [docs/modules/inventory.md](modules/inventory.md).
- **Admin** — branches, departments, posts, org-chart, RBAC permission matrix (`area:operation:scope`), in-section nav (`AdminNav`), dummy-org seeding. See [docs/modules/admin.md](modules/admin.md).
- **Settings** — pipelines, statuses, sub-statuses, org-defaults, year-ending, naming-convention, printer-settings, in-section nav (`SettingsNav`). See [docs/modules/settings.md](modules/settings.md).
